# Mira Pico 无人机气体监测与地面站

本项目将 Mira Pico 输出的时间、CH4、H2O、C2H6 和经纬度，通过既有 E28 2.4 GHz LoRa 透明串口链路发送到 Windows 地面站。地面站提供实时数值、三通道曲线、CSV 保存、丢包统计，以及交互式 SSH 终端。

本文按当前代码整理，更新于 **2026-10-14**。已有硬件连接、模块参数和通信链路保持不变。

## 1. 通信与运行位置

```text
Mira Pico 内部数据输出
        │ RS232 数据口
        ▼
pico_ch4_bridge.py（在 Pico 的 Debian 中运行）
        │ USB 串口
        ▼
机载 E28 LoRa 模块 ── 无线透明传输 ── 地面 E28 LoRa 模块
                                            │ USB / COM 串口
                                            ▼
                               mira_ground_station.py（Windows）
```

SSH 使用另一条已有连接：**地面电脑连接 Pico Wi-Fi，再登录 Pico 的 Debian**。SSH 与文件下载不通过 LoRa 传输；串口监测和 SSH 终端可同时使用。

| 文件 | 用途 |
| --- | --- |
| `pico_ch4_bridge.py` | 读取仪器完整行，提取字段并发送 `$MIRA` 帧 |
| `mira_ground_station.py` | Windows 监测界面、CSV 保存和交互式终端 |
| `启动地面站.bat` | 寻找 Python 并启动地面站 |
| `Pico数据格式.txt` | 仪器 17 列输出示例 |
| `beacon_tx.py` / `beacon_rx.py` | 独立的编号帧链路测试工具 |
| `data/` | 地面站 CSV、上次串口和 Pico 地址记录 |

现有操作手册、开发日志和项目背景文档保留了历史说明，其中部分字段、终端实现和拓扑描述早于当前代码。日常操作以本文和当前脚本为准。

## 2. 安装与启动

### Windows 地面电脑

安装 Python 3，在**用于启动地面站的同一个 Python 环境**中执行：

```powershell
python -m pip install pyserial matplotlib "pywinpty>=2,<3" "pyte>=0.8,<0.9"
```

- `pyserial`：串口接收，监测功能必需。
- `matplotlib`：实时曲线；缺失时仍可接收数据，但没有曲线。
- `pywinpty`、`pyte`：Windows 交互终端和终端屏幕解析。缺失时监测仍可用，SSH 终端会提示安装依赖。
- SSH 和 SCP 使用 Windows OpenSSH 客户端，可在本地终端用 `ssh -V` 检查是否可用。

在项目目录启动：

```powershell
python .\mira_ground_station.py
```

也可以双击 `启动地面站.bat`。当前批处理只会尝试安装 `pyserial` 和 `matplotlib`，**不会安装 `pywinpty` 和 `pyte`**，交互终端依赖需先按上面的命令安装。

### Pico 的 Debian

发送端只依赖 `pyserial`：

```bash
python3 -m pip install --user pyserial
```

若使用已有 `pico-lora` 服务，请确保依赖能被该服务使用的 Python 解释器导入。

| 配置 | 当前值 |
| --- | --- |
| 仪器数据口 `SRC` | `/dev/ttyUSB_RS232` |
| LoRa 模块口 `DST` | `/dev/ttyUSB_LORA` |
| 串口波特率 `BAUD` | `9600` |
| 发送帧长度上限 | 121 字节，包含末尾换行 |

两个路径是既有串口别名，需分别指向正确设备。保持现有波特率和模块参数。

已有服务的状态与控制命令：

```bash
systemctl status pico-lora
sudo systemctl stop pico-lora
sudo systemctl start pico-lora
```

手动验证前先停止已有服务，避免同时读取同一个仪器串口：

```bash
python3 /home/debian/pico_ch4_bridge.py --dry-run
```

`--dry-run` 仍读取真实仪器串口，只打印提取后的帧，不打开 LoRa 发送口；它不是离线样例模式。按 Ctrl+C 结束后，可以重新启动服务。

未配置服务时，也可手动运行 `python3 /home/debian/pico_ch4_bridge.py`。手动启动不会自动建立开机自启；上述脚本位置按实际部署路径调整。

## 3. 地面站监测

1. 关闭占用 LoRa COM 口的 PuTTY 或其他串口程序。
2. 在“监测”页选择实际 COM 口，或直接输入端口名；波特率使用 `9600`。
3. 点击“连接”。“自动存 CSV”默认勾选。
4. 查看三种气体数值与曲线，以及 Pico 时间、纬度、经度、帧数、速率和丢包率。
5. 结束时点击“断开”或关闭程序，已收齐的队列数据会在关闭 CSV 前处理。

曲线最多保留最近 **300 个接收点**，横轴按电脑接收时间计算。显示窗口与 CSV 保存独立，旧点离开曲线窗口不会删除已保存的数据。“重置统计”清空统计和当前曲线，不删除 CSV。

地面站串口读线程异常时会显示断开状态，排除问题后需要重新连接。发送端串口异常时会关闭旧端口并重新打开，端口打开失败每 2 秒重试。

## 4. 数据格式与缺测值

仪器输入必须是一行 **17 列**的逗号分隔数据。当前提取的列如下：

| 字段 | 输入列号（从 1 开始） | 单位或格式 |
| --- | --- | --- |
| Time Stamp | 1 | `MM/DD/YYYY HH:MM:SS`，可带小数秒 |
| CH4 | 7 | ppm |
| H2O | 8 | ppm |
| C2H6 | 9 | ppb |
| Latitude | 16 | 纬度 |
| Longitude | 17 | 经度 |

坐标顺序为 **先纬度、后经度**。发送帧是 ASCII 文本，以 `\n` 结束：

```text
$MIRA,<seq>,<timestamp>,<CH4>,<H2O>,<C2H6>,<Latitude>,<Longitude>
```

例如：

```text
$MIRA,0,05/12/2026 15:44:27.507,2.31506,15724.4,5.41189,31.230416123,121.473701234
$MIRA,1,05/12/2026 15:44:28.500,2.31825,15713.5,5.85,nan,nan
```

处理规则：

- 气体字段的 `nan`、`No Data`、空值及非有限数字统一为 `nan`，保留同一行其他有效字段。缺测气体在数值卡显示 `No Data`，曲线在该点断开。
- 坐标的缺失值、非有限数字和非数字内容统一为 `nan`，界面显示 `No Data`。有效坐标保留原始数字精度。
- 数字 `0`、负数和高浓度仍作为测量值保留。程序没有添加平滑或峰值过滤。
- 两端等待完整换行后再处理，不把串口超时返回的半行直接当成完整数据。
- 仪器输入的缺列、非法时间、非法气体内容及非 ASCII 字节会被拒绝；地面站也校验帧头、字段数量、时间和气体格式。
- 超过 121 字节的发送帧会跳过并记录原因，不截断数字；异常长输入也会丢弃，不无限累积缓冲。

地面站继续兼容旧的 `$MIRA,seq,timestamp,CH4,H2O,C2H6` 帧，以及无序号旧帧；缺少坐标时显示 `No Data`。无序号帧无法单独提供丢包统计。

## 5. CSV 与日志

CSV 位于程序所在目录的 `data/` 下，每 **30 分钟**轮转一次。文件名包含微秒，避免同秒开关保存时混入同一个文件：

```text
data/mira_20261014_153000_123456.csv
```

列顺序固定为：

```csv
pc_time,seq,pico_time,CH4_ppm,H2O_ppm,C2H6_ppb,Latitude,Longitude
```

`pc_time` 是电脑收到完整行的时间，`pico_time` 是仪器原始时间。旧帧无序号时 `seq` 留空，缺测字段保存为 `nan`。写入失败会停止本次存盘并提示错误，监测可继续；排除问题后可重新勾选自动保存。

**地面站 CSV 是传输字段记录，不是仪器完整 17 列原始数据。** 桥接脚本也不负责保存仪器完整原始文件。Pico 自身原始文件的实际存储目录尚未确认，需登录设备查找。

其他记录：

- `data/last_port.txt`：上次成功连接的 COM 口。
- `data/last_host.txt`：手动记住的 Pico SSH 地址。
- 地面站“导出日志”：导出当前保留的监测日志文本，不等同于完整历史 CSV。
- Pico `/tmp/ch4_bridge.log`：桥接运行日志，约 1 MiB 轮转，保留 2 个备份；位于临时目录，不应当作永久测量档案。

## 6. 内置 SSH 终端

1. 电脑连接 Pico Wi-Fi，打开“终端 / 远程控制”页。
2. 填写 `debian@实际IP`，可点击“记住”。IP 按设备实际地址填写，不预设固定网关。
3. 点击“SSH 登录”。首次连接按 OpenSSH 提示确认主机信息；如需密码，直接输入。
4. 登录后可以执行 Linux 命令，工作目录等状态保留在同一个 SSH 会话中：

```bash
pwd
ls -lah
cd /home/debian
ls
```

可直接点击终端区域输入，也可使用底部“命令 / 输入”框后按 Enter。Tab 补全和方向键交互应在终端区域使用；Ctrl+C 中断当前命令，Ctrl+Shift+C 复制选中文本，Ctrl+V 粘贴。密码提示会尝试自动隐藏底部输入，也可手动勾选“隐藏输入”。

输入 `exit` 结束 SSH 会话。需要执行 Windows 命令时点击“本地终端”；该按钮会结束当前终端会话并启动本地 `cmd.exe`，不是在 Pico 上打开另一个 shell。

停止采集、启动采集、查看状态、查看日志、重启和关机等快捷操作会打开独立的内置终端窗口，不打断主 SSH 会话。`sudo` 如需密码，可在对应窗口输入。免密登录是可选配置。

### 查找并下载 Pico 原始数据

先在 SSH 会话中用 `pwd`、`ls` 确认实际文件路径。随后点击“本地终端”，在电脑端运行 SCP。以下 IP 和路径均需替换成实际值：

```text
scp debian@实际IP:/实际原始数据路径/文件.csv .
scp -r debian@实际IP:/实际原始数据目录 .
```

末尾的 `.` 表示电脑当前目录。内置本地终端初始工作目录为程序所在目录，可以先用 Windows 的 `cd /d "目标目录"` 切换下载位置。SCP 下载需在**本地终端**执行，而不是在已经登录的 Pico shell 中执行。

## 7. 丢包统计与排查

地面站按当前统计段中首个和最后一个编号帧推算预期帧数，使用递增编号帧的接收计数计算丢包率。重复编号和无序号帧不会冲高编号接收计数。发送端序号回退且 Pico 时间前进时，会重新开始该段丢包统计。

该统计不覆盖首帧之前或末帧之后的丢失，也不统计发送端在校验或长度检查阶段跳过的数据。如果设备重启时仪器时钟也回退，可手动点击“重置统计”。

| 现象 | 检查方式 |
| --- | --- |
| COM 口打不开 | 检查实际端口、USB 连接，以及是否被其他程序占用 |
| 没有监测数据 | 检查 `pico-lora` 状态、两个串口别名、发送端日志和既有 LoRa 配置 |
| GPS 显示 `No Data` | 查看仪器自身是否有有效定位；缺测不会阻止气体传输 |
| 曲线出现尖峰 | 先核对对应 CSV 和仪器原始数据；当前代码不按浓度大小过滤数据 |
| CSV 停止保存 | 查看写入错误、目录权限和可用空间，恢复后重新启用保存 |
| SSH 终端无法启动 | 在启动程序的 Python 环境中检查 `pywinpty`、`pyte` 和 Windows OpenSSH |
| SSH 无法连接 | 确认电脑已连 Pico Wi-Fi、地址正确且设备 SSH 服务可用 |

现有帧没有应用层校验码。如果损坏后的内容仍是合法数字、字段数也正确，软件无法仅凭格式校验确定它是否是真实测量值。

## 8. 独立链路测试工具

`beacon_tx.py` 和 `beacon_rx.py` 用于编号帧测试，不采集气体，也不使用 `$MIRA` 数据格式。测试时使用独立接收脚本，避免与地面站争用同一个 COM 口。

Windows 先启动接收端，将 `COM3` 替换成实际端口：

```powershell
python .\beacon_rx.py --port COM3 --baud 9600 --expected-frames 120 --idle-timeout 5
```

在连接机载 LoRa 模块的 Linux 设备上启动测试发送端，替换实际串口：

```bash
python3 beacon_tx.py --port /dev/ttyUSB0 --baud 9600 --frequency 2 --duration 60
```

该示例预期 120 帧，编号从 1 开始。接收端收齐预期帧，或首个有效帧之后连续 5 秒未收到新的有效帧时结束；也可按 Ctrl+C 结束并保存统计。测试 CSV 默认名为 `beacon_rx_YYYYMMDD_HHMMSS.csv`。两份测试脚本同样要求 `9600` 波特率。
